# check_fs_throughput gate data — variant: tests
#
#     scripts/check_fs_throughput.sh --variant tests --emit-allowlist
#
# Counts per MiB are deterministic for one ISO and carry caps. The
# filesystem-over-raw write-rate ratio is the only quantity here that is
# invariant under a change of accelerator, so it is the only rate graded.
# Floors exist so a measurement that stopped happening cannot read as free.
# The write window flushes to quiescence at both ends, so a count is the whole
# cost of getting 2 MiB onto the medium.
#
# A cap matching nothing is a dead entry and fails the gate — except the
# capacity rows (FSCAP), which a run without `CAPACITY_IMG` attached
# legitimately does not report. `--require-capacity` (what `just
# test-capacity` passes) turns that skip back into a failure. The FSPERF rows
# come from a full `builddir/run_tests --raw` capture, the FSCAP rows from a
# `just test-capacity` boot of the same tree.

# 2 MiB through write(2) is 10 transactions and 10 commit records; a
# transaction per 4 KiB reports 256 per MiB, which this cap stops.
max-txns-per-mib	post-kernel-tests	8
max-commits-per-mib	post-kernel-tests	8
# Block-layer write requests: about one per transaction beyond the data, 24
# per MiB measured. The eager flusher can wake inside the window and split
# what one pass coalesces, so a loaded host can exceed it: re-run, do not
# raise it, while txns and commits keep their shape.
max-devwrites-per-mib	post-kernel-tests	29
# Sectors written: what logging a payload instead of writing it home costs,
# which the request cap cannot see (4650 sectors for 2 MiB, 1.13x).
max-devblocks-per-mib	post-kernel-tests	2891
max-barriers-per-mib	post-kernel-tests	8
# The filesystem's write rate over the same run's raw device rate, 8–16%
# measured: two single timings on a shared machine, so the floor (a quarter
# under the lowest) catches a collapse to a transaction per 4 KiB (~1.5%),
# not a 2x regression, which the per-MiB caps catch.
min-fs-over-raw-pct	post-kernel-tests	6
# The window wrote what it claims to have measured.
min-bytes	post-kernel-tests	1572864

# The 16 GiB capacity volume (`just test-capacity`) mounts in 26–27 device
# reads: geometry plus the journal's block map, not a sweep of the volume.
max-mount-reads-per-gib	post-kernel-tests	3
# The second lookup of the last of 4000 names. A name-index hit is a candidate
# whose record is read and compared, so a cold block costs a read; 0 is a warm
# cache, and 8 the budget the directory-index test asserts. The first lookup
# is not graded: a rolled-back allocation retracts the index, and the next
# lookup rebuilds it by scanning.
max-lookup-reads	post-kernel-tests	8
min-volume-gib	post-kernel-tests	16
min-dirents	post-kernel-tests	3000
# The volume holds a checkout of this repository and the pinned toolchain
# sysroot, which the guest walks back as 5445 files of 1105385677 bytes;
# these floors are that padded a quarter down, because a volume that stopped
# being populated looks like a tree that got cheap to walk.
min-files	post-kernel-tests	4083
min-treebytes	post-kernel-tests	829039257
