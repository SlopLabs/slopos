# check_quota_headroom gate data — variant: tests
#
#     scripts/check_quota_headroom.sh --variant tests --emit-allowlist
#
# One line per <phase> <TAB> <kind> <TAB> <cap>, where the cap is the
# highest peak any single account row reached for that kind. Measured,
# never chosen: raise a cap only with a fresh --emit-allowlist in the
# same commit, and say in the message what started consuming more.
#
# A cap matching nothing is a dead entry and fails, because a kind that
# stopped being reported looks exactly like a kind that stayed cheap.
#
# Caps on the rows that move between runs of one ISO -- kernelmeta, pages,
# residentpages, diskblocks, pinnedbytes, task -- keep the previously tracked
# value where it still holds, since one capture is a point and not a spread;
# the deterministic rows and every new row carry this capture's exact peak.
# The task row after userland rose from 10 with `install_test`, which runs
# `/bin/bootctl` as a child; it is timing-dependent, and two captures of one
# tree measured 11 and 12, then 13 once an interrupt-delivered wake preempted
# an equal-priority task and an enqueue behind a running task began kicking an
# idle CPU: more of the userland suite's children overlap, and 14 once the
# flusher wrote data without the mount lock and file faults stopped sharing
# one I/O mutex, and 16 once `pthread_kill` reached a thread: the libc ABI
# test holds one of its own blocked, and a jobserver helper thread that used
# to outlive its process by a second of failed shutdown now exits with it, so
# the children the suite starts overlap differently. The process row fell
# from 256 to 20 because an exited process is now torn down and retired
# instead of leaking until shutdown, and rose to 21 with that same scheduling
# change, since its peak is how many exited children are still being torn
# down while the next ones start, and to 23 with the same `pthread_kill`
# change. The commitpages row
# after userland is the build-loop tests reserving six tenths of the
# headroom, which moves with usable memory and with what else holds a
# promise at that moment: three captures measured 120 266, 120 318 and
# 120 319, then two captures of the in-guest toolchain work 120 602 each, then
# 121 633 once slibc's allocator became a per-thread segment allocator, whose
# 4 MiB segments are promised whole, and the cap is the largest. The expected refusals are the kernel stest that lowers the
# root ceiling and over-asks once, then the build-loop utest: its over-ask is
# refused twice, because the mmap handler reclaims and retries a refused
# request once, and its fork past the ceiling is refused once. The pages row
# after the kernel tests is test_fork_and_exec_walk_what_is_mapped_not_what_is_reserved
# holding a 1 GiB MAP_NORESERVE reservation in a parent and in its fork, which
# the row counts twice: captures measured 538 714, 535 332, 538 832, 539 004
# and 539 006, and the cap is the largest.

# The peak of a kind nobody exercised is zero, and a cap derived from
# it would bound nothing. Every listed kind must have been reached.
min-kinds 2
min-kinds-for boot 1

# A denial is an over-limit charge. Under quota=warn it is granted and
# counted, so a non-zero total means the enforced tier would have
# refused something — which is a finding, not a pass.
max-denials 0

# The refusals the suite provokes on purpose, held to their exact count:
# fewer means a test stopped refusing, more means something else was.
expect-denials post-kernel-tests commitpages 1
expect-denials post-userland-tests commitpages 4

# The charge path's cost, as ratios rather than cycle counts. A cycle
# count here measures the accelerator: the same tree reports ~1500
# cycles per charge under KVM and ~20000 under TCG, and both are
# correct. Every number below is x100, so 420 means 4.20.
#
# The reference floors are emitted at half the observed value, because
# a bare CAS is relatively dearer under TCG than natively and this
# ratio does move with the accelerator. They prove the measurement
# happened; the depth ratio below is the check.
min-charge-over-reference 1 982
min-charge-over-reference 7 3759
max-depth-cost-ratio 7 478

# A physical bound on the reference, not a measurement.
