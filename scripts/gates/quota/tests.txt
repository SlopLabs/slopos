# check_quota_headroom gate data — variant: tests
#
#     scripts/check_quota_headroom.sh --variant tests --emit-allowlist
#
# One line per <phase> <TAB> <kind> <TAB> <cap>, where the cap is the
# highest peak any single account row reached for that kind. Measured,
# never chosen: raise a cap only with a fresh --emit-allowlist in the
# same commit, and say in the message what started consuming more.
#
# A cap matching nothing is a dead entry and fails, because a kind that
# stopped being reported looks exactly like a kind that stayed cheap.
#
# Caps on the rows that move between runs of one ISO -- kernelmeta, pages,
# residentpages, diskblocks, pinnedbytes, task -- keep the previously tracked
# value where it still holds, since one capture is a point and not a spread;
# the deterministic rows and every new row carry this capture's exact peak.
# The task row after userland rose from 10 with `install_test`, which runs
# `/bin/bootctl` as a child; it is timing-dependent, and two captures of one
# tree measured 11 and 12, then 13 once an interrupt-delivered wake preempted
# an equal-priority task and an enqueue behind a running task began kicking an
# idle CPU: more of the userland suite's children overlap, and 14 once the
# flusher wrote data without the mount lock and file faults stopped sharing
# one I/O mutex, and 16 once `pthread_kill` reached a thread: the libc ABI
# test holds one of its own blocked, and a jobserver helper thread that used
# to outlive its process by a second of failed shutdown now exits with it, so
# the children the suite starts overlap differently. The process row fell
# from 256 to 20 because an exited process is now torn down and retired
# instead of leaking until shutdown, and rose to 21 with that same scheduling
# change, since its peak is how many exited children are still being torn
# down while the next ones start, and to 23 with the same `pthread_kill`
# change. The commitpages row
# after userland is the build-loop OOM test's hog, which promises the whole
# headroom less 3072 pages so its forked child's writes outrun the ceiling:
# two captures measured 193 853 each. The expected refusals count through
# both phases. The kernel phase refuses four: the stest that lowers the root
# ceiling and over-asks once, the forked child's write past a full ceiling
# (tests_commit), and the COW signal frame pushed into a full ceiling on the
# syscall-exit and the IRQ-exit roads (tests_build_floor_signal). The userland
# phase adds three: the build-loop over-ask is refused twice, because the mmap
# handler reclaims and retries a refused request once, and the hog's forked
# child has one write refused before the OOM killer takes the hog. The
# residentpages row after the kernel tests rose from 772 to 2049 once a memfd
# charged its sizer's resident pages at ftruncate rather than when mapped: the
# OOM tests size 64-page memfds per process, and one row holds a 2048-page
# memfd. The boot kernelmeta row measured 1708, and 1713 once every disk went
# through the block layer and NVMe: the controllers' queues and engines, the
# disk registry and the devfs node table. A boot on which an AP is slow to
# answer its startup peaks 48 pages higher, 1761, and the wired network's
# table of published NICs and their handles adds 4 at every AP timing (1666,
# 1713 and 1761 on the tree before it, 1670, 1717 and 1765 on it), so 1765 was
# the cap. The `qemu-xhci` and scratch stick `just test` attaches from USB mass
# storage on are bound at boot: the controller's device table and rings, the
# stick's device, transport and engine. On a host without KVM the tree before
# it peaked at 1766 and this one at 1800, 1801, 1802 and 1802 over four boots,
# so 1802 is the cap.
# The kernelmeta row after the kernel tests measured 6230 and 6192 in
# two captures once the OOM and signal tests spawned more processes, then
# 6290, 6229 and 6283 in three once slibc gained the functions git needs, then
# 6292, 6294, 6196, 6298, 6197, 6213, 6240 and 6199 in eight once every test
# boot attached and mounted a labelled media volume, then 6226, 6313, 6255,
# 6306 and 6320 in five once the volumes became ext4 — a jbd2 journal keeps
# its superblock and an escape map per mount, and the suite gained the ext4
# and journal tests — then 6321, 6271, 6321, 6312 and 6322 in five once the
# crash store's tests opened stores over scratch disks, all but 6271 on boots
# whose AP answered late, then 6526, 6514 and 6528 in three once a basefs test

# grow, and the block-ceiling test made a user task, then 6552 in one whose
# new tests hold nothing past their end (the PTY echo test leaves the root's
# kernelmeta where it found it), then 6578, 6615, 6663, 6670, 6672, 6672 and
# 6681 in seven once the wired network landed. The previous tree's kernel
# measured 6472 on this host against the same images, and the peak sat 384
# pages above what the phase ends holding in every run of both: the growth is
# in what the drivers and net suites leave allocated (each suite alone: 188 to
# 234 and 242 to 262 pages, the two virtio-net tests that moved into the
# drivers suite and the NIC tests), while core, fs, mm and sched end where
# they did. Then 6628, 6689, 6628, 6586 and 6695 in five once full speed
# landed, whose kernel tests allocate nothing: the two highest ended 61 and 67
# pages above the others too, the late-AP spread the boot row records, and the

# The peak of a kind nobody exercised is zero, and a cap derived from
# it would bound nothing. Every listed kind must have been reached.
min-kinds 2
min-kinds-for boot 1

# A denial is an over-limit charge. Under quota=warn it is granted and
# counted, so a non-zero total means the enforced tier would have
# refused something — which is a finding, not a pass.
max-denials 0

# The refusals the suite provokes on purpose, held to their exact count:
# fewer means a test stopped refusing, more means something else was.

# The charge path's cost, as ratios rather than cycle counts. A cycle
# count here measures the accelerator: the same tree reports ~1500
# cycles per charge under KVM and ~20000 under TCG, and both are
# correct. Every number below is x100, so 420 means 4.20.
#
# The reference floors are emitted at half the observed value, because
# a bare CAS is relatively dearer under TCG than natively and this
# ratio does move with the accelerator. They prove the measurement
# happened; the depth ratio below is the check.

max-depth-cost-ratio 7 478
