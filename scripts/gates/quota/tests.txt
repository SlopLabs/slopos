# check_quota_headroom gate data — variant: tests
#
#     scripts/check_quota_headroom.sh --variant tests --emit-allowlist
#
# One line per <phase> <TAB> <kind> <TAB> <cap>, where the cap is the
# highest peak any single account row reached for that kind. Measured,
# never chosen: raise a cap only with a fresh --emit-allowlist in the
# same commit, and say in the message what started consuming more.
#
# A cap matching nothing is a dead entry and fails, because a kind that
# stopped being reported looks exactly like a kind that stayed cheap.
#
# Measured on the tests ISO under quota=enforce, with the session-smoke utest
# holding a desktop-shaped population open across the post-userland-tests
# dump. All eight kinds are charged.
#
# `pages` is mapped **virtual** address space, not resident memory -- the
# RLIMIT_AS quantity. The root's 612 416 pages is 2.3 GiB of VA across ~108
# live address spaces against 86 899 physical pages of RAM, and those two
# numbers are not comparable *by design*: demand paging means a process may
# map far more than it ever populates. The reconciling number is the per-row
# one -- worst single address space 30 998 pages (121 MiB) -- which is what
# the enforced per-process ceiling was derived from. That ceiling is now
# 1 048 576 (4 GiB of VA) and is no longer derived from a measurement at all:
# with lazy mappings a VA charge bounds no memory, so `Pages` is a stated
# `RLIMIT_AS` and `residentpages` below is the number that tracks what is
# actually held.
#
# The caps are the ROOT account's peaks — the sum over every principal plus
# the kernel's own, not a per-process figure. Worst single user rows measured
# 18 fdslot / 10 objectrow / 4 process / 1 task / 12 kernelmeta, against
# enforced per-process defaults of 256 / 512 / 64 / 512 / 2048. Both numbers
# matter and they live in different places on purpose: this file is the gate
# ceiling, the enforced runtime defaults are in abi/src/quota.rs. Deriving
# either from the other would make the ratchet measure its own configuration.
#
# kernelmeta is two things summed on the root. Task stacks are 12 pages each
# — a 32 KiB kernel stack plus a 16 KiB SafeStack data stack — and are the
# deterministic half; the kernel heap's own backing is the other, every page
# the size-class slabs and the large-alloc tier take from the buddy, charged
# once at the allocator so the root's row stays reconcilable against the
# buddy's allocated count. The `memory` kconsole command prints both numbers
# side by side for exactly that comparison.
#
# The heap half is why these caps carry visible slack rather than sitting one
# observation above the measurement: a slab refill happens on whichever
# allocation first empties a class, so the peak moves with test order.
#
# `process` at 113 against ~109 live account rows is not a leak: the userland
# phase spawns a test binary per utest and most are still referenced at the
# dump point.
#

# The charge path's cost. It runs on every syscall that allocates, so a
# regression here is a whole-kernel throughput regression -- Escort measured
# end-to-end accounting at 8 %, and 15-50 % under load with protection domains.
# Without a check here a change of that size passes every other check in this
# file.
#
# Expressed as ratios, never as cycle counts. A cycle count on this path
# measures the *accelerator*: the caps this file used to carry (3000 and 9000)
# were taken on a KVM host, and the identical unmodified tree reports 20631 and
# 81886 under TCG. That gate failed on every machine without /dev/kvm, which is
# a gate measuring the host and calling it the kernel -- the same defect the
# suite's own wall-clock assertions had.
#
# One cap and two floors. All ratio values are x100, so 420 reads as 4.20.
#
#   max-depth-cost-ratio <depth> <cap>          -- the check
#       Depth 7 against depth 1. Each level is meant to add a bounded constant,
#       so this stays near 4 and a walk that stopped amortising goes to 7 or
#       beyond. It is the only quantity here that is invariant under a change
#       of accelerator, which is why it is the only one carrying a ceiling.
#
#   min-charge-over-reference <depth> <floor>   -- a measurement floor
#       One charge+refund round trip against one bare uncontended CAS round
#       trip, measured in the same run, the same batch shape and the same
#       interrupts-off window. This is deliberately a FLOOR and not a cap: the
#       ratio itself moves with the accelerator (a CAS is relatively dearer
#       under TCG than natively, so the same tree reads ~18x here and would read
#       far more under KVM), so a ceiling measured on one accelerator would fail
#       on the other -- the exact defect this file's history is about. What a
#       floor can do is prove the charge path still performs the atomic work it
#       is supposed to.
#
#   min-reference-cycles <floor>                -- a measurement floor
#       An absolute floor on the reference itself, because the two floors above
#       are ratios over it and a reference that collapsed to 1 satisfies both.
#       Not a measurement: a `lock cmpxchg` round trip through memory is not
#       under a couple of dozen cycles on any real or emulated x86, so this is
#       a physical bound and stays valid whatever runs the guest.
#
# **What is NOT checked, stated plainly:** a slowdown that scales the whole
# charge path uniformly -- every depth, and a bare CAS with it -- passes every
# line above. Catching that needs an absolute cycle ceiling, and an absolute
# cycle ceiling is what this file used to carry and what failed on every machine
# without /dev/kvm. Restoring one costs a measurement on each accelerator CI
# might use, which nobody has; a gate nobody can run green is worse than a gate
# with a stated hole.

# The tightest quantity in this file: 3.77 and 3.86 in the two pinned runs that
# reached the report, 3.69-3.99 across the earlier runs. The cap is 5.00; a walk
# that stopped amortising goes to 7.00 (one full charge per level) or beyond.
max-depth-cost-ratio 7 500

# Floors, emitted at half the TCG observation. TCG is the conservative source
# for these: it makes an atomic relatively dearer than the surrounding work, so
# charge-over-CAS is *lower* here (18.5x at depth 1) than it would be natively.
min-charge-over-reference 1 900
min-charge-over-reference 7 3400

# The denominator those two divide by. A physical bound, not a measurement.
min-reference-cycles 20
